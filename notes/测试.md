## Burp Suite



### 1. Burp Intruder 爆破（Brute Force 模块）

**目标**：爆破 DVWA 的登录密码，理解自动化攻击原理。

**步骤**：

- 抓取登录请求（GET 方式，参数 `username` 和 `password`）。
- 发送到 Intruder，标记两个参数位置，攻击类型选择 **Cluster bomb**（笛卡尔积）。
- 加载字典（用户名：`admin`；密码：`password`、`123456` 等）。
- 开始攻击，根据响应长度或内容判断成功（但 Low 难度下成功与失败的长度相近，需手动查看响应）。

**遇到的问题**：

- 社区版 Intruder 有速度限制（演示模式），但功能正常。
- 爆破结果中所有响应长度几乎相同（5090~5091），因为 DVWA 登录成功和失败页面长度差异极小。

**解决方法**：

- 手动在浏览器中登录确认凭据（`admin` / `123456`）。
- 使用 Burp 的 `Grep - Match` 功能标记 `Welcome` 关键词，自动识别成功登录。

**知识点**：

- Intruder 四种攻击类型：Sniper（单参数多负载）、Battering ram（多参数相同负载）、Pitchfork（多参数一一对应）、Cluster bomb（笛卡尔积）。

- 社区版限制：速度慢，无保存攻击配置功能。

  ![img](https://raw.githubusercontent.com/hsg1224/network/main/img/屏幕截图 2026-05-14 194457.png)

------



```
| 模式 | 原理 | 请求总数 | 适用场景 |
|------|------|----------|----------|
| **Sniper** | 每次替换一个 payload 位置，其他位置保持原值；依次遍历所有位置 | `payload数量 × 位置数` | 单参数爆破（如固定用户名，爆破密码） |
| **Pitchfork** | 同时替换所有位置，每个位置取对应顺序的 payload；多个 payload 集合长度需相同 | `max(各payload集合长度)` | 用户名与密码一一对应的情况（如 `admin:admin`、`root:root`） |
| **Cluster bomb** | 笛卡尔积：每个位置的 payload 与所有其他位置的 payload 组合 | `payload1数量 × payload2数量 × ...` | 完全未知的用户名和密码组合，暴力枚举 |
```

### 2. Decoder 模块：编码与解码

**功能**：对文本进行编码（Encode）和解码（Decode），支持 URL、Base64、HTML、Hex 等。

**实操**：

- 将 URL 编码的字符串 `%3Cscript%3Ealert(1)%3C/script%3E` 解码为 `<script>alert(1)</script>`。
- 将明文 `admin:123456` 进行 Base64 编码得到 `YWRtaW46MTIzNDU2`，再解码回原文。

**技巧**：

- 多层编码需要多次解码（例如先 URL decode，再 Base64 decode）。

- `Smart decode` 可自动尝试多种解码方式。

  ![image-20260514205145409](https://raw.githubusercontent.com/hsg1224/network/main/img/image-20260514205145409.png)

### 3. Comparer 模块：对比两个请求/响应

**功能**：对比两个数据（可以是请求、响应或任意文本）的差异，支持单词级别（Words）和字节级别（Bytes）对比。

**操作流程**：

1. 在 Proxy 或 Repeater 中选中两个数据，右键 → `Send to Comparer`。
2. 切换到 Comparer 标签，点击 **Words**（按单词对比）或 **Bytes**（按字节对比）。
3. 查看高亮差异：红色表示修改，蓝色表示新增/删除。

**实际应用**：

- 对比登录成功（`password=123456`）和登录失败（`password=password`）的响应，找出差异位置。
- Bytes 视图以十六进制显示，需结合 ASCII 理解差异内容。

**解决的问题**：

- 响应长度相近时，通过 Comparer 精确定位不同字符。

## **Burp Suite Repeater 高级用法**

### 1. Repeater 模块核心技巧

- **手动修改参数**：在 Repeater 中直接编辑请求行，支持任意 payload。
- **URL 编码处理**：当 Burp 不自动编码空格时，需手动将空格替换为 `%20`（例如 `id=1%20and%201=2`），否则后端可能无法正确解析。
- **发送与观察**：点击 `Send` 后，响应区域显示结果。使用 `Ctrl+F` 搜索 `exists` 或 `MISSING` 快速判断。
- ![img](https://raw.githubusercontent.com/hsg1224/network/main/img/屏幕截图 2026-05-15 202641.png)

### 2. 盲注基础验证

- **数字型注入**：不需要引号，直接使用逻辑运算。
- **有效 payload**：
  - `1 and 1=1` → exists
  - `1 and 1=2` → MISSING
- 通过 Repeater 可以快速切换 payload，验证漏洞存在。

### 3. 利用 Comparer 对比响应

- 将两个不同响应的请求（如 `1 and 1=1` 和 `1 and 1=2`）分别发送到 Comparer。
- 在 Comparer 中点击 `Words` 或 `Bytes`，可清晰看到 `exists` 和 `MISSING` 的差异位置。
- ![image-20260515204933091](https://raw.githubusercontent.com/hsg1224/network/main/img/image-20260515204933091.png)

### 4. 盲注猜解数据库信息

- **猜长度**：`1%20and%20length(database())=4` → exists（数据库名长度 4）。
- **猜第一个字符**：`1%20and%20ascii(substr(database(),1,1))>100` → exists（实际 ASCII 为 100，即字符 'd'）。
- 

### 5. 今日演示的 payload 成功列表

| Payload（URL 编码后）                         | 含义                   | 结果         |
| :-------------------------------------------- | :--------------------- | :----------- |
| `1%20and%20length(database())=4`              | 数据库名长度是否为 4   | exists（真） |
| `1%20and%20ascii(substr(database(),1,1))>100` | 第一个字符 ASCII > 100 | exists（真） |

- ## CSP Bypass 模块总结

  ### 1. 什么是 CSP？

  CSP（Content Security Policy，内容安全策略）是一种浏览器安全机制，通过 HTTP 响应头或 `<meta>` 标签定义页面允许加载的资源来源（脚本、样式、图片等），用于防止 XSS、数据注入等攻击。

  ### 2. 常见 CSP 指令

  - `script-src`：控制 JavaScript 的来源。
  - `style-src`：控制 CSS 的来源。
  - `default-src`：其他指令的默认值。
  - `object-src`、`frame-src` 等。

  ### 3. CSP 策略值

  - `'self'`：只允许同源资源。
  - `'unsafe-inline'`：允许内联脚本/样式（危险）。
  - `'unsafe-eval'`：允许 `eval()` 等动态执行。
  - `'nonce-<base64>'`：要求内联脚本携带相同的 `nonce` 属性。
  - `'sha256-<hash>'`：允许内容哈希匹配的内联脚本。
  - 域名/路径：允许加载指定域的脚本（如 `https://cdn.example.com`）。

  ### 4. DVWA 中的实践

  #### Low 难度

  - **策略**：`script-src 'self' https://pastebin.com hastebin.com ...`（白名单多个域名）

  - **绕过方法**：利用白名单内的域名托管恶意脚本，例如：

    - 在 Pastebin 创建内容为 `alert(1)` 的 Paste，获取 Raw 链接。
    - 若 Raw 链接 Content-Type 不是 `application/javascript`，需用 Burp 修改响应头；或直接使用 `cdn.jsdelivr.net`（返回正确 MIME）。

  - **成功条件**：脚本被加载并执行。

    输入https://cdn.jsdelivr.net/gh/hsg1224/network/alert.js

    ![image-20260519202142621](https://raw.githubusercontent.com/hsg1224/network/main/img/image-20260519202142621.png)

  #### Medium 难度

  - **策略**：`script-src 'self' 'unsafe-inline' 'nonce-TmV2ZXIgZ29pbmcgdG8gZ2l2ZSB5b3UgdXA='`

  - **特点**：虽然包含 `unsafe-inline`，但一旦指定 `nonce`，浏览器忽略 `unsafe-inline`，只允许携带正确 `nonce` 的内联脚本或同源脚本。

  - **绕过方法**：

    - 发现 `nonce` 值是静态的（`TmV2ZXIgZ29pbmcgdG8gZ2l2ZSB5b3UgdXA=`，解码为 "Never going to give you up"）。

    - 直接在注入点（如反射型 XSS 参数）插入：

      html

      ```
      <script nonce="TmV2ZXIgZ29pbmcgdG8gZ2l2ZSB5b3UgdXA=">alert(1)</script>
      ```

      

    - 成功弹出警告框。

      ![image-20260519203734153](https://raw.githubusercontent.com/hsg1224/network/main/img/image-20260519203734153.png)

  ### 5. 关键知识点

  - **`nonce` 的作用**：一次性随机数，用于精确授权单个内联脚本。
  - **静态 nonce 是漏洞**：如果 `nonce` 不变化，攻击者可直接复用。
  - **`unsafe-inline` 与 `nonce` 的优先级**：同时存在时，`nonce` 优先，`unsafe-inline` 失效。
  - **绕过思路**：
    - 利用白名单域加载外部脚本（需注意 MIME 类型）。
    - 复用已知的 `nonce` 或哈希。
    - 寻找配置缺陷（如 `script-src` 允许 `data:` 或 `blob:`）。

  ### 6. 防御建议

  - 使用 `nonce` 或哈希，并确保其随机且不可预测。
  - 避免同时使用 `unsafe-inline` 和 `nonce`。
  - 限制白名单域为严格可信的 CDN。
  - 启用 `strict-dynamic` 配合 `nonce` 增强安全性。



### Cryptography 模块（Medium 难度）—— AES-ECB 块移动攻击

#### 1. 目标

利用三个已知 token（Sooty admin 过期、Sweep user 过期、Soo user 有效），伪造一个以 `Sweep` 用户登录且具有 `admin` 权限的有效 token。

#### 2. 核心原理

- 加密模式：**AES-128-ECB**（电子密码本模式），相同明文块产生相同密文块，各块独立。
- 攻击方法：**块移动攻击**（又称为“剪切攻击”），从不同 token 中提取所需的功能块（用户块、时间戳块、权限块、填充块），重新拼接成新的合法密文。

#### 3. 实施步骤

- 从页面获取三个 token 的完整十六进制字符串（每个 192 字符）。
- 按每 32 字符（16 字节）切分为 6 个密文块。
- 选择拼接：
  - 第 1 块：来自 `Sweep`（用户标识）
  - 第 2 块：来自 `Soo`（有效时间戳）
  - 第 3 块：来自 `Sooty`（admin 权限）
  - 第 4-6 块：来自 `Soo`（保证总长度一致）
- 将拼接后的新 token 提交至页面。

#### 4. 遇到的问题与解决

- **Python 环境问题**：Kali 禁止直接 `pip install` 系统包，通过创建虚拟环境（`python3 -m venv`）安装 `pycryptodome` 解决。
- **脚本运行错误**：`Odd-length string` 因 token 字符串换行导致长度奇数，修正为连续字符串后解决。
- **密钥未知**：由于 ECB 攻击不需要解密，最终放弃解密思路，直接使用块拼接成功。
- **靶机 PHP 错误**：提交 token 后出现 `openssl_decrypt` 未定义错误，但不影响伪造结果（后端验证可能另有逻辑），最终页面显示 `Welcome administrator Sweep`，表示成功。

#### 5. 成果

成功绕过加密保护，以 `Sweep` 身份获得管理员权限。理解了 ECB 模式的严重弱点以及如何在不破解密钥的情况下伪造数据。

## DVWA - JavaScript Attacks 模块

### 2.1 校验逻辑

- 页面加载时执行 `generate_token()`：
  ```javascript
  document.getElementById("token").value = md5(rot13(phrase));
  ```

- 服务端收到请求后，用相同的算法计算期望 token 并与提交的 token 比较。
- **问题**：`generate_token()` 只在页面加载时调用一次，不会随输入框内容变化自动更新。

### 2.2 绕过方法

1. 在输入框中输入 `success`（不要提交）。

2. 打开控制台（F12），执行：

   javascript

   ```
   generate_token();
   ```

   

3. 点击 `Submit` 按钮，成功。

   ![image-20260521200908284](https://raw.githubusercontent.com/hsg1224/network/main/img/image-20260521200908284.png)

### 2.3 原理

手动触发 token 重新生成，让隐藏字段的值与当前输入内容匹配。

## 四、三个难度对比总结

| 难度   | 服务端校验公式                  | 前端行为                        | 绕过核心                          |
| :----- | :------------------------------ | :------------------------------ | :-------------------------------- |
| Low    | `md5(rot13(phrase))`            | token 只在页面加载时生成一次    | 手动执行 `generate_token()`       |
| Medium | `reverse("XX" + phrase + "XX")` | 延迟 300ms 生成一次，无输入监听 | 手动执行 `do_elsesomething("XX")` |

## 五、核心安全启示

1. **客户端校验不可信**：用户可任意修改 DOM、覆写 JavaScript 函数、直接发送 HTTP 请求。
2. **任何 token 生成逻辑如果在客户端实现，就等于没有防护**。
3. **安全的 token 必须由服务端随机生成**（如 session 绑定的 CSRF token），并与用户输入无关。
4. **即使服务端校验了 token，若前端可以直接调用 token 生成函数，攻击者依然能绕过**（Low/Medium 就是例子）。
